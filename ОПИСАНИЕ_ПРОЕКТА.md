# MicShot — надстройка Excel для отчётов о проблемах

**Версия:** 7.5 (2026-10-28) · **Платформа:** Excel 365, классическое приложение Windows · **Права администратора: не нужны**

MicShot решает сценарий «рассказать и показать проблему»: пользователь нажимает одну кнопку, говорит в микрофон и кликами показывает, где болит. На выходе — самодостаточная папка-кейс: голос, его расшифровка, полный журнал действий, скриншоты и копия самой книги. Кейс отправляется в службу поддержки одной кнопкой (API и авторизация настраиваются конфигом).

## Пайплайн одного кейса

```
[Старт записи] → голос (WAV, кусками) + полоса-субтитры (живой текст с ~10-й секунды)
              → журнал действий (события Excel + 3 слоя детектора форматирования)
              → скриншоты (по действиям, с дебаунсом + периодические)
[Стоп]        → склейка кусков в narration.wav → расшифровка (по фрагментам, повтор пропущенного)
              → копия книги в папку кейса → итоговый дифф форматирования
[Диалог]      → текстовый комментарий → список того, что уйдёт → [Отправить]
              → zip → multipart POST (ретраи с backoff) → send_result.txt
```

## Кнопки (вкладка «Надстройки» → раздел MicShot)

| Кнопка | Действие |
|---|---|
| **Отчёт: старт записи** | Одна кнопка-тумблер: клик — старт (звук + журнал + скриншоты + полоса-субтитры); при записи кнопка нажата и читается «Отчёт: стоп + открыть папку» |
| **Скриншот сейчас** | Одиночный снимок окна → PNG в «Документы» |
| **Панель** | Показать/скрыть полосу-субтитры во время записи |
| **Ключ API…** | `asr_config.txt` — сервер распознавания речи (LAN-Whisper / облако) |
| **Настройки отправки…** | `send_config.txt` — API, авторизация, таймауты и повторы отправки кейсов |

## Состав кейса (папка в «Документах»)

| Файл | Что это |
|---|---|
| `narration.wav` | Голос (44,1 кГц / 16 бит / моно). Пишется кусками (stop+save — надёжнее паузы), на стопе склеивается с валидацией RIFF-чанков и числовым порядком (корректно от 100 кусков) |
| `transcript.txt` | Расшифровка целиком (UTF-8): пофрагментно, успешные фрагменты переиспользуются, повторяются только пропущенные |
| `actions_log.bas` | Полный журнал действий как VBA-код с метками времени (импортируется и запускается `RecordedActions`) |
| `shot_NNN_act/per_*.png` | Скриншоты окна: act — по действиям пользователя, per — периодические |
| `<Книга>.xlsx` | Копия книги на момент стопа — папка самодостаточна для отправки целиком |
| `comment.txt` | Текстовый комментарий пользователя (UTF-8), пишется в диалоге после стопа |
| `send_result.txt` | Итог отправки: SENT/FAILED + число попыток + ответ/ошибка сервера |

## Журнал действий — что пишется

- **Лист**: выделение ячеек, ввод значений (с прежним значением «было: …»), правый/двойной клик, активация/уход/удаление листов, пересчёт формул (дебаунс 5 с), гиперссылки, обновление сводных и умных таблиц.
- **Форматирование — три слоя** (у Excel нет событий на ленту):
  1. *выделение* — мгновенный дифф «отпечатка» формата (шрифт, начертание, цвет текста, заливка, границы, выравнивание, перенос, объединение, числовой формат, высота/ширина, скрытость);
  2. *видимая область* — каждые 2 с, свойства читаются массивами (один COM-вызов на свойство), дифф по адресам ячеек: ловит кисть форматирования и вставку с форматом ВНЕ выделения;
  3. *итоговый дифф* — снимок формата листов на старте сравнивается на стопе: гарантия, что изменения за пределами экрана не потеряны.
- **Окно/книга**: масштаб, автофильтр/фильтрация, размер окна, создание/открытие/закрытие/сохранение/печать книг, переключение книг.
- Не видны событиями (только на скриншотах): клики по ленте, сортировка, вставка/удаление строк без изменения значений.

## Живая расшифровка (полоса-субтитры)

Полупрозрачная полоса без рамки и кнопок у низа окна Excel. При старте — подсказка, первый кусок уходит на сервер через 10 с (`FIRST_LIVE_TICK_SEC`), дальше каждые `live_sec` (по умолчанию 30). HTTP асинхронный: `WinHttpRequest` + `WaitForResponse(0)` в цикле опроса, зависший запрос отменяется через 30 с — **Excel не замирает**, микрофон пишет дальше во время запроса. Сервер недоступен → после 3 неудач живые тики отключаются, полная расшифровка всё равно будет на стопе. Исходные куски удаляются только после успешных склейки + распознавания + сохранения текста; при сбое остаются в кейсе.

## Отправка кейса (v7.5)

`%APPDATA%\MicShot\send_config.txt` — шаблон создаётся автоматически, кнопка «Настройки отправки…» открывает в Блокноте:

```
endpoint=https://support.example.com/api/cases   # пуст = не настроено
auth=none|bearer|basic|header                    # схема авторизации
token=…  login=…  password=…  header_name=X-API-Key
project=                    # метка проекта в кейсе (опционально)
file_field=file             # имя поля формы для zip
timeout_sec=120  retry_count=3  retry_delay_sec=5  retry_backoff=2
```

- **Отправляется**: zip всей папки кейса + поля формы — `report_id`, `project`, `machine`, `user`, `app_version`, `recorded_at`, `comment` (multipart POST, UTF-8).
- **Надёжность**: ретраи с нарастающей паузой (delay·backoff^(N−1)) только для устранимых ошибок (сеть/таймаут/5xx/429/408); постоянные 4xx не ретраятся зря. Таймауты и число попыток — из конфига.
- **Прозрачность**: каждая попытка логируется в `%APPDATA%\MicShot\send_log.txt`; итог — `send_result.txt` в кейсе (с ответом сервера, включая id кейса); пользователь получает ясное сообщение — успех с id / «не настроено» с путём к конфигу / «не отправлено» с причиной и куда смотреть. Папка кейса при любой неудаче остаётся на диске.
- **Диалог после стопа** (`MicShotSendForm`): список файлов кейса с размерами, поле комментария, кнопки «Отправить» / «Не отправлять». Комментарий сохраняется в `comment.txt` в любом случае.

## Сборка и качество

Исходники VBA — heredoc-и внутри `build_micshot.ps1`: модуль `MicShot`, классы `AppEvents` / `CSapiEvents`, формы `MicShotForm` (субтитры) и `MicShotSendForm` (отправка). `MicShot_source.bas` — экспорт для чтения.

Цикл разработки: `python _vba_lint.py` → `_sync_source.ps1` → `_build_staging.ps1` → тесты (на staging-файле) → `build_micshot.ps1` при закрытом Excel (установка). Имя staging-файла — `MicShot_staging.xlam`: Excel конфликтует с установленной надстройкой того же имени и `Workbooks.Open` падает.

`_vba_lint.py` закрывает классы ошибок, реально стоившие часов отладки: дубли процедур и `Dim`; использование переменной до её `Dim` («Duplicate declaration»); модульные `Const` после первой процедуры; **`ByVal`-массивы** (VBA запрещает — «Array argument must be ByRef»); **`Exit Function` внутри `Sub`**; обращения к процедурам, удалённым при рефакторинге. Линтер проверяет и код, выгруженный из собранного .xlam (ground truth), а не только heredoc-и.

Ловушки платформы, учтённые в коде: `save` на приостановленной записи MCI вешает драйвер (пишем кусками stop+save); 1-базный массив в COM-запросе сдвигается на байт (тела 0-базные); `Shell CopyHere` в скрытых сессиях молчит (zip через `Compress-Archive`); `Do While Not EOF(f)` при несуществующем файле с `On Error Resume Next` зацикливается вечно (проверка `Dir$` до `Open`); `NumberFormat` из COM в русской локали требует `NumberFormatLocal`.

## Установка / удаление

`dist\` — пакет раздачи: `MicShot.xlam`, `install_micshot.bat` (HKCU, без админа), `uninstall_micshot.bat` (полное удаление; конфиг и отчёты — по вопросу), `ИНСТРУКЦИЯ.txt`.
